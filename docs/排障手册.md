# 排障手册

按「症状 → 原因 → 解决」组织，覆盖部署、MCP 接入、数据与前端的常见问题。

---

## 部署

### 1. `container aiagent-server has no healthcheck configured`

```
✘ Container aiagent-server   Error dependency server failed to start
dependency failed to start: container aiagent-server has no healthcheck configured
```

**原因**：`web` 服务用 `depends_on: server: condition: service_healthy`，但 `server` 没定义 `healthcheck`
（`server/Dockerfile` 里的 `HEALTHCHECK` 是注释状态），compose 判定依赖不可用。

**解决**：在 `docker-compose-full.yml` 的 server 服务补上 healthcheck（alpine 自带 busybox `wget`）：

```yaml
healthcheck:
  test: ["CMD-SHELL", "wget --no-verbose --tries=1 --spider http://localhost:8080/api/health || exit 1"]
  interval: 30s
  timeout: 5s
  start_period: 30s
  retries: 3
```

`start_period` 给后端建表 / 迁移 / 种子数据留时间，避免启动慢被判 unhealthy。

### 2. postgres 起不来，日志提示权限问题

**原因**：`data/postgres_data` 属主不是 `999`（pgvector 官方镜像内 postgres 用户的 uid）。
由宿主机创建目录时属主是当前用户（如 1000），容器内进程无写权限。

**解决**：

```bash
sudo chown -R 999:999 data/postgres_data
```

`make init` 已内置该逻辑（属主已是 999 时自动跳过）。无 sudo 权限会打印提示，需手动执行。

> 换 alpine 基础镜像时 postgres 用户 uid 通常是 `70`，需同步调整。

---

### 3. `make init` 报 `sudo: a password is required`

```
sudo: a terminal is required to read the password
```

**原因**：非交互终端下 `sudo` 无法输入密码。

**影响**：无害。`chown` 前有属主判断、`chown` 后有 `|| echo` 兜底，目录已创建，继续执行 `make up` 即可；
仅当 postgres 起不来时再手动 chown（见上一条）。

---

### 4. 改了前端/后端代码，重启后没生效

| 原因 | 解决 |
|------|------|
| 用了 `make up-nc`（不重建镜像） | 改用 `make up`（`up -d --build`） |
| 浏览器缓存了 `index.html` | 强刷，或 `docker compose -f docker-compose-full.yml exec web nginx -s reload` |
| 改的文件被 `.dockerignore` 排除 | 检查 `web/.dockerignore`、`server/.dockerignore` |

`web/Dockerfile` 在镜像内完成 `npm install` + `npm run build`，本地 `web/dist` 不进镜像，无需先本地构建。

## MCP 接入

### 5. 第三方 MCP 返回 `404 Not Found`，`path` 是 `/sse`

```
MCP 返回 404: {"timestamp":"...","path":"/sse","status":404,"error":"Not Found","requestId":"..."}
```

**原因**：`sse` 传输目前是简化实现——`internal/mcpclient/client.go` 的 `doRequest` 直接对 `srv.URL`
发起 POST，未按 MCP 规范先 `GET /sse` 建流、再从 `event: endpoint` 取消息端点。高德等标准 SSE 服务端的
`/sse` 只接受 GET，POST 即 404。

**解决**：改用 **streamable_http 传输 + `/mcp` 端点**（两者是不同端点，不是同一 URL 换传输类型）：

| 配置项 | 值 |
|--------|-----|
| Transport | `streamable_http` |
| URL | `https://mcp.amap.com/mcp?key=你的Key` |

验证（不打库，直连对方端点）：

```bash
curl -s -X POST "https://mcp.amap.com/mcp?key=你的Key" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

连通性排查工具：`cd server && AMAP_MCP_KEY=你的Key go run ./mcp_probe`

> 该 404 响应体是 Spring Boot 风格（`timestamp` / `path` / `requestId`），出现这种格式即可判定是对方服务端返回，不是平台路由问题。

## 数据与种子

### 6. 发布校验里「已绑定数据源」一直不通过

**原因**：旧实现用 `KnowledgeBase.FileCount` 判断知识库是否为空，而该冗余字段只在种子数据里自增过，
真实上传链路从未维护，恒为 `0` → doc 类智能体永远判不通过。

**现状**：已改为按发布快照里冻结的知识库绑定（`snap.Resources.KnowledgeBaseIDs`）统计
`files` 表中 `status = ready` 的记录数（`store.CountFilesInKnowledgeBases`）。
提示文案也区分了两种情形：未绑定知识库 / 已绑定但无就绪文档。

**自查**：

```bash
# 该智能体绑定的知识库下有多少已就绪文档
docker compose -f docker-compose-full.yml exec -T postgres psql -U postgres -d aiagent \
  -c "SELECT knowledge_id, status, count(*) FROM files GROUP BY 1,2;"
```

### 7. 改了 `seedSkillLibrary`，重启后技能库没变化

**原因**：种子数据只在表为空时写入（`Count() > 0` 直接 return），已有数据的库不会被覆盖。

**解决**：

```bash
make db-reset-skills
```

等价命令：

```bash
docker compose -f docker-compose-full.yml exec -T postgres psql -U postgres -d aiagent \
  -c "DELETE FROM skill_libraries;"
docker compose -f docker-compose-full.yml restart server
```

> 清空会重建 ID，已引用旧技能的智能体需要重新挂载。

## 前端

### 8. 某个页面宽度被限制（如文件管理页不像其他列表页满宽）

排查组件内的 `max-width`：

```bash
grep -rn "max-width" web/src/views
```

`FileList.vue` 曾有 `max-width: 1200px`，已改为 `width: 100%` 与其他列表页保持一致。

## 常用排查命令

```bash
make ps                                                        # 服务状态
make logs                                                      # 跟踪全部日志
docker compose -f docker-compose-full.yml logs -f server       # 只看后端
docker compose -f docker-compose-full.yml logs -f postgres     # 只看数据库
docker compose -f docker-compose-full.yml config               # 校验 compose 文件语法
docker compose -f docker-compose-full.yml exec -T postgres \
  psql -U postgres -d aiagent -c "\dt"                         # 列出数据表
```
